레지스터는 SRAM인가?

둘 다 빠른 저장 회로이지만 설계 목적과 구조를 구분해야 합니다.

CPU 레지스터

수십~수백 개 단위

실행에 바로 쓰는 데이터, PC, 상태·제어 정보를 저장.

주로 플립플롭 / 래치 기반 회로

일부 구현에는 작은 SRAM형 배열도 사용될 수 있음.

SRAM 캐시와 DRAM

KB → MB → GB

캐시는 주소/태그를 기준으로 데이터를 저장하는 작은 고속 메모리. DRAM은 큰 용량 제공.

저장 밀도와 접근 시간이 다른 계층

r15와 p15는 왜 전혀 다른가?

r은 CPU의 작업 레지스터 번호, p는 구형 ARM의 코프로세서 번호입니다.

r13 / r14 / r15

r13 = SP (Stack Pointer)
r14 = LR (Link Register)
r15 = PC (Program Counter)

CPU의 데이터·실행 흐름 레지스터.

p13 / p14 / p15

p13 = CP13 번호
p14 = CP14 (디버그 계열)
p15 = CP15 (시스템 제어)

MRC p15의 p15는 PC가 아닙니다.

ONE THING
“r15=PC”와 “p15=시스템 제어 코프로세서”는 다른 번호 체계다.
CP: Coprocessor · SP: Stack Pointer · LR: Link Register

ALU와 시프트: 곱셈이 쉬워 보이는 이유

2의 거듭제곱은 왼쪽 시프트로 계산할 수 있습니다. 다만 모든 곱셈이 한 번의 시프트는 아닙니다.

시프트로 2배·4배

0100← 1칸1000
4 × 2 = 8
0011← 2칸1100
3 × 4 = 12

3배는 어떻게 계산?

3N = (N << 1) + N
ADD r1, r0, r0, LSL #1

예: r0=5 → r1=15

단, 실제 컴파일러는 상황에 따라 MUL을 선택할 수도 있습니다.

주의
왼쪽 시프트는 고정 폭 정수에서 오버플로·부호 해석에 주의해야 합니다.
ONE THING
2배는 1칸, 4배는 2칸, 3배는 “2배 + 원래 값”으로 이해하면 된다.
LSL: Logical Shift Left · ALU: Arithmetic Logic Unit

소수점 수는 왜 정수 시프트만으로 해결되지 않을까?

정수는 비트 이동이 직관적이지만 소수점은 별도의 표현 규칙과 연산이 필요합니다.

정수 · Integer

5 × 2 = 10

이진 정수 0101 → 1010

비트 시프트가 자연스럽다.

고정소수점 · Fixed point

1.5 ≙ 15 / 10

정해진 배율을 기준으로 정수처럼 연산.

임베디드 DSP에서 활용.

부동소수점 · Floating point

1.5 × 2.5 = 3.75

IEEE 754의 부호·지수·가수 규칙.

SIMD/FP 연산 유닛 사용.

연결
온디바이스 AI INT8 양자화는 실수를 스케일·제로포인트로 정수에 매핑해 빠르게 처리하는 대표 사례입니다.
ONE THING

Banked register: IRQ가 와도 원래 스택을 지키는 방법

ARMv7의 일부 실행 모드는 SP·LR 등을 별도로 보관합니다.

일반 실행

r13_svc = SP_svc
r14_svc = LR_svc
CPSR = 현재 상태

현재 모드에 맞는 물리 저장 공간이 보입니다.

IRQ 예외 진입

r13_irq = SP_irq
r14_irq = LR_irq
SPSR_irq ← 이전 CPSR

예외 처리용 스택과 복귀 정보를 분리합니다.

중요한 주의
모든 r0~r15가 모드별로 독립적인 것은 아닙니다. 주로 SP/LR과 일부 모드의 추가 레지스터가 banked입니다.
ONE THING
Banked는 “이름은 같아도 모드에 따라 다른 저장 공간을 본다”는 뜻이다.
SPSR: Saved Program Status Register · IRQ: Interrupt Request

Permission Fault: CPU가 출입을 거부하는 순간

잘못된 주소뿐 아니라 허가 없는 읽기·쓰기·실행도 예외를 만들 수 있습니다.

1. VA가 매핑되지 않음

페이지 테이블에 유효한 항목이 없으면 translation fault.

2. 권한이 불일치

읽기 전용 페이지에 쓰거나 NX 페이지에서 실행하면 fault.

3. 커널이 원인을 분석

Cache clean, invalidate, barrier의 차이

이 명령들을 동의어처럼 사용하면 데이터 손실이나 stale data 문제가 생깁니다.

CLEAN

변경된 캐시 데이터가 지정한 가시성 지점까지 반영되도록 함.

Cache → Memory

INVALIDATE

캐시 엔트리를 무효화하여 이후 최신 값을 가져오도록 함.

Old Cache ↛

BARRIER

완료·순서·명령 인출 동기화를 보장하기 위한 장벽.

DMB / DSB / ISB
명령쉽게 풀이
DMB메모리 접근 순서를 보장
DSB지정 영역의 선행 작업 완료 대기
ISB뒤따르는 명령어가 변경된 실행 문맥을 사용
ONE THING
정답은 “언제나 invalidate”가 아니다. 데이터의 소유자·접근 방향·공유 조건을 먼저 파악해야 한다.
