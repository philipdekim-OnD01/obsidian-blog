/home/philip/bin 코드 아키텍처

이 페이지는 라즈베리파이의 /home/philip/bin 폴더에 있는 운영 코드의 역할과 연결 구조를 정리한 문서다. 핵심은 8080 웹 대시보드, 카메라 촬영, 사람 감지, synthetic DVS 합성, event synthesis 데모, 정리/변환/헬스체크 작업자가 느슨하게 연결된 구조다.

1. 전체 실행 구조

camera_snapshot.sh
  -> /home/philip/camera_snapshots/*.jpg
  -> detect-queue event

person_yolo_worker.py
  -> person_detect.py
  -> /home/philip/person_snapshots/*.jpg
  -> synthesis-queue event

person_synthesis_worker.py
  -> trigger_person_synthesis.py
  -> synthesize_virtual_dvs_grid.py
  -> /home/philip/synthetic_frames/{id}/

camera_gallery_server.py  : port 8080 main dashboard
synthetic_grid_server.py  : port 8081 synthetic video browser

event_synthesis_demo.py / realtime_event_synthesis_demo.py
  -> /home/philip/event_synthesis_demo/output/*.mp4 + metrics json

maintenance
  -> disk_usage_guard.py
  -> prune_similar_snapshots.py
  -> convert_*_h264.py
  -> camera_stack_healthcheck.sh
데이터 중심 구조

스크립트들이 직접 서로를 오래 붙잡고 호출하기보다, 이미지 폴더와 queue 폴더를 통해 느슨하게 연결된다.

웹서버는 표시 담당

camera_gallery_server.py는 합성 계산을 직접 하지 않고, 이미 생성된 이미지/영상/메트릭을 읽어 보여준다.

합성은 별도 작업

synthetic DVS와 event synthesis는 별도 스크립트가 생성하고, 결과물만 웹에 붙는다.

운영 안정성

disk guard, prune, healthcheck, h264 변환 스크립트가 저장공간과 재생 호환성을 관리한다.

4. 카메라 촬영과 사람 감지 파이프라인

  -> read detect-queue
  -> run person_detect.py
  -> enqueue synthesis if person exists

  -> preprocess with letterbox
  -> OpenCV DNN inference
  -> save person crop/frame
  -> capture burst sequence

중복 실행을 막기 위해 lock file을 사용한다. 촬영 결과를 snapshot 폴더에 저장하고, 후속 감지를 위해 queue 파일을 만든다.

person_yolo_worker.py

queue worker다. 감지 작업이 많아져도 촬영 루프와 분리된다. 감지 성공 시 합성 queue를 만든다.

person_detect.py

YOLO 모델을 직접 실행하는 파일이다. detector, burst capture, detection save, synthesis trigger 연결이 포함된다.

person_synthesis_worker.py

합성 요청을 모아서 실행한다. 같은 시간에 여러 감지 이벤트가 몰려도 합성을 과도하게 중복 실행하지 않게 한다.

5. Synthetic DVS 생성 계층

synthesize_virtual_dvs_grid.py는 실제 DVS 센서가 없는 상황에서, CIS 이미지 변화로부터 가상의 DVS event stream과 DVS 스타일 영상을 만든다. 지금 수정된 방향은 흰 배경이 아니라 어두운 DVS grid 위에 additive event trail을 렌더링하는 구조다.

입력:
  /home/philip/camera_snapshots/*.jpg
  /home/philip/person_snapshots/*.jpg

주요 처리:
  make_virtual_event_mask()
    -> 두 CIS 이미지 차이에서 움직임 mask 추출

  make_virtual_dvs_npz()
    -> log(after) - log(before)
    -> random noise injection
    -> acceleration curve + jitter trajectory
    -> virtual DVS npz 저장: x, y, t, p

  window_dvs_npz()
    -> target time 주변 event 선택
    -> accumulation + exponential decay
    -> positive/negative event heat 생성

  synth_between()
    -> dark DVS grid background
    -> additive blending
    -> label + frame 저장

출력:
  /home/philip/synthetic_frames/{id}/
    {id}.mp4
    {id}_*.jpg
    virtual_dvs/{id}_pair*.npz
    meta.json

trigger_person_synthesis.py는 이 합성을 직접 호출하는 orchestration 파일이다. 최신 person snapshot과 burst frame을 골라 source sequence를 만들고, 합성 결과가 생기면 mail queue까지 연결할 수 있다.

9. 운영 관점에서 봐야 할 병목

  • 촬영 병목: camera capture가 느려지면 감지와 합성 모두 입력이 늦어진다.
  • YOLO 병목: person detector가 queue를 처리하지 못하면 synthesis queue가 늦게 생긴다.
  • 합성 병목: synthetic DVS와 realtime event synthesis는 OpenCV/NumPy/ffmpeg를 사용하므로 CPU와 memory bandwidth 영향을 크게 받는다.
  • 웹 병목: 8080/8081은 계산보다 파일 제공이 중심이다. 대형 MP4를 여러 클라이언트가 동시에 재생하면 I/O가 병목이 될 수 있다.
  • 저장공간 병목: snapshot, synthetic frame, MP4, npz가 빠르게 쌓인다. disk guard와 prune 정책이 중요하다.
