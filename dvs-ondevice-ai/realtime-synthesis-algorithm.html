Realtime Event Synthesis Demo 코드 구조와 합성 알고리즘

이 페이지는 /home/philip/bin/realtime_event_synthesis_demo.py의 실제 구현을 기준으로, 이미지가 행렬로 바뀌고, DVS event가 누적/감쇠되며, 비어 있는 timestamp의 배경 이미지가 보간되고, 최종 합성 프레임이 만들어지는 과정을 쉽게 설명한다.

1. 코드 전체 구조

1환경 설정

EVENT_DEMO_WIDTH, TARGET_OUTPUT_FPS, WALL_SECONDS로 출력 해상도와 목표 FPS를 정한다.

2입력 로드

timestamp.txt, CIS 이미지 *.jpg, DVS event *.npz를 읽는다.

3좌표 스케일링

원본 DVS 좌표 1920x1080을 출력 이미지 크기 w x h로 변환한다.

4event memory

event_memory[h,w] 행렬에 양/음 이벤트를 누적하고 매 프레임 감쇠한다.

5배경 보간

현재 CIS 이미지와 다음 CIS 이미지를 약하게 섞어 anchor frame을 만든다.

6합성/인코딩

anchor에 event contrast를 더하고, 양/음 이벤트를 색으로 표시한 뒤 MP4에 기록한다.

main()
  load timestamp.txt, image_paths, event_paths
  first = cv2.imread(...)
  first = fit_width(first)
  sx = output_width / SOURCE_WIDTH
  sy = output_height / SOURCE_HEIGHT
  event_memory = zeros(h, w)

  while wall clock time remains:
      target_t = first_timestamp + frame_count / target_fps
      interval = timestamp interval containing target_t
      load base image, next image, and interval event npz
      scale event x/y coordinates
      event_memory *= EVENT_DECAY
      add events up to target_t into event_memory
      alpha = position between base and next timestamp
      anchor = weak interpolation(base, next_img)
      synth = anchor + event_memory * CONTRAST_GAIN
      write synth frame to video

2. 처음 들어온 이미지가 행렬로 변환되는 과정

CIS 이미지는 일반적으로 JPEG/BMP 같은 파일이다. OpenCV의 cv2.imread는 이 파일을 숫자 행렬로 읽는다. 컬러 이미지는 보통 height x width x 3 배열이고, 각 픽셀은 B, G, R 세 채널의 밝기값 0~255를 가진다.

first = cv2.imread(str(image_paths[0]), cv2.IMREAD_COLOR)
first = fit_width(first)
h, w = first.shape[:2]
base = first.astype(np.float32)

예를 들어 2x2 컬러 이미지는 개념적으로 아래처럼 바뀐다.

이미지 픽셀:
  좌상단 어두움, 우상단 회색, 좌하단 파랑, 우하단 흰색

행렬 BGR:
[
  [[ 10,  10,  10], [120, 120, 120]],
  [[255,  20,  20], [255, 255, 255]]
]

float32 변환:
[
  [[ 10.0,  10.0,  10.0], [120.0, 120.0, 120.0]],
  [[255.0,  20.0,  20.0], [255.0, 255.0, 255.0]]
]

astype(np.float32)를 쓰는 이유는 event 값을 더하고 보간할 때 소수점 연산과 clipping이 필요하기 때문이다. 마지막에만 다시 uint8로 바꿔 MP4에 기록한다.

3. 센서 해상도 차이와 좌표 스케일링

코드에서는 DVS 원본 좌표계를 SOURCE_WIDTH=1920, SOURCE_HEIGHT=1080으로 가정한다. 출력 영상은 TARGET_WIDTH에 맞춰 줄어든다. 그래서 event 좌표도 같은 비율로 줄여야 한다.

sx = output_width / source_width
sy = output_height / source_height
x_out = round(x_event * sx)
y_out = round(y_event * sy) 
sx = w / SOURCE_WIDTH
sy = h / SOURCE_HEIGHT

xs = np.rint(z["x"] * sx).astype(np.int32)
ys = np.rint(z["y"] * sy).astype(np.int32)
valid = (0 <= xs) & (xs < w) & (0 <= ys) & (ys < h)
xs, ys = xs[valid], ys[valid]

가상 예시: DVS가 1920x1080이고 출력이 480x270이면 sx=0.25, sy=0.25다. event 좌표 (1000, 400)은 출력 좌표 (250, 100)이 된다.

SOURCE = 1920 x 1080
OUTPUT = 480 x 270
sx = 480 / 1920 = 0.25
sy = 270 / 1080 = 0.25

event (x=1000, y=400)
=> (round(1000*0.25), round(400*0.25))
=> (250, 100)

이 구현은 가장 단순한 비례 스케일링이다. 두 센서의 화각, 렌즈 왜곡, 장착 위치가 완전히 같다는 가정을 깔고 있다. 실제 하드웨어에서는 이보다 더 정확한 homography, undistortion, calibration matrix가 필요할 수 있다.

4. 이벤트 누적과 감쇠

DVS 이벤트 하나는 보통 (x, y, t, p) 형태다. x,y는 위치, t는 timestamp, p는 밝기가 증가했는지 감소했는지를 뜻한다. 코드에서는 event_memory라는 2D 행렬에 이 이벤트들을 누적한다.

event_memory = np.zeros((h, w), np.float32)

event_memory *= EVENT_DECAY
np.add.at(event_memory, (slice_y[pos], slice_x[pos]), 1.0)
np.add.at(event_memory, (slice_y[~pos], slice_x[~pos]), -1.0)

EVENT_DECAY=0.70은 이전 이벤트 흔적을 매 프레임 70%만 남긴다는 뜻이다. 그러면 움직임 흔적이 잠깐 남았다가 사라진다.

가상 3x3 event_memory 시작:
[
  [0, 0, 0],
  [0, 0, 0],
  [0, 0, 0]
]

양 이벤트: (x=1, y=1, p=+1)
음 이벤트: (x=2, y=1, p=-1)

누적 후:
[
  [0,  0,  0],
  [0, +1, -1],
  [0,  0,  0]
]

다음 프레임 감쇠 EVENT_DECAY=0.70:
[
  [0,   0,    0],
  [0, +0.7, -0.7],
  [0,   0,    0]
]

np.add.at을 쓰는 이유는 같은 픽셀에 여러 이벤트가 동시에 들어와도 덮어쓰지 않고 모두 더하기 위해서다. 예를 들어 같은 좌표에 양 이벤트 3개가 들어오면 값이 1이 아니라 3이 된다.

5. 비어 있는 timestamp의 이미지를 만드는 수학적 적분 구조

CIS는 낮은 FPS로 들어오고 DVS는 그 사이의 변화량을 촘촘하게 준다. 그래서 없는 중간 이미지는 “이전 CIS 이미지에, 그 이후 발생한 밝기 변화 이벤트를 시간 방향으로 적분해서 더한다”라고 생각하면 쉽다.

I(x,y,t) = I(x,y,t0) + k * integral E(x,y,tau) d tau
discrete version:
I_hat[x,y,t] = anchor[x,y,t] + gain * sum(decayed polarity events at x,y)

코드에서는 완전한 물리 기반 로그 밝기 복원까지 하지는 않고, 실시간 데모에 맞춰 간단한 근사식을 쓴다.

signed = np.clip(event_memory, -10.0, 10.0)
synth = np.clip(anchor + signed[:, :, None] * CONTRAST_GAIN, 0.0, 255.0)

여기서 event_memory는 “시간 적분된 변화량”이고, CONTRAST_GAIN=4.8은 이벤트 변화량을 실제 픽셀 밝기 변화처럼 보이게 키우는 계수다. 양 이벤트는 밝게, 음 이벤트는 어둡게 또는 다른 색으로 표시된다.

예시:
anchor pixel = [100, 100, 100]
event_memory = +2
CONTRAST_GAIN = 4.8

synth = [100,100,100] + 2*4.8
      = [109.6,109.6,109.6]
      => 약간 밝아진 픽셀

event_memory = -3 이면:
synth = [100,100,100] - 14.4
      = [85.6,85.6,85.6]
      => 어두워진 픽셀

6. 배경 이미지 보간과 결합

코드는 현재 CIS 이미지 base와 다음 CIS 이미지 next_img 사이의 시간 위치를 alpha로 계산한다. 다만 데모에서는 과도한 잔상을 막기 위해 다음 이미지를 아주 약하게만 섞는다.

alpha = clip((target_t - t0) / (t1 - t0), 0, 1)
anchor = cv2.addWeighted(base, 1.0 - 0.12 * alpha,
                         next_img, 0.12 * alpha,
                         0.0)

일반적인 선형 보간은 (1-alpha)*base + alpha*next다. 이 데모는 next_img 반영률을 최대 12%로 제한한다. 이유는 실제 event overlay 효과를 보여주는 데 집중하고, 서로 다른 시간의 CIS 이미지가 많이 섞여 흐릿해지는 것을 줄이기 위해서다.

base pixel = 100
next pixel = 160
alpha = 0.5

일반 보간:
  100*(1-0.5) + 160*0.5 = 130

현재 코드:
  base weight = 1 - 0.12*0.5 = 0.94
  next weight = 0.12*0.5 = 0.06
  100*0.94 + 160*0.06 = 103.6

그 다음 event_memory를 더하고, 이벤트 위치를 색으로 강조한다.

pos_map = event_memory > 0.5
neg_map = event_memory < -0.5

synth[pos_map] = synth[pos_map] * (1 - OVERLAY_GAIN) + red_color * OVERLAY_GAIN
synth[neg_map] = synth[neg_map] * (1 - OVERLAY_GAIN) + blue_color * OVERLAY_GAIN

8. 실제 구현 방식과 한계

처리현재 코드 구현의미와 한계
프레임 시간 생성target_t = timestamps[0] + frame_count * 1_000_000 / TARGET_OUTPUT_FPS원하는 출력 FPS에 맞춰 가상의 프레임 timestamp를 만든다.
이벤트 구간 선택np.searchsorted(timestamps, target_t)현재 target timestamp가 어느 CIS 이미지 사이에 있는지 찾는다.
좌표 스케일링np.rint(z["x"] * sx), np.rint(z["y"] * sy)단순 비례 변환이다. 화각/왜곡/센서 위치 차이는 보정하지 않는다.
이벤트 정렬np.argsort(ts, kind="stable")timestamp 순서대로 누적하기 위한 단계다.
누적/감쇠event_memory *= 0.70, np.add.at(...)실시간 데모에는 직관적이지만 Python/NumPy random scatter 병목이 생긴다.
배경 보간cv2.addWeighted(base, 1-0.12a, next, 0.12a, 0)중간 프레임의 배경을 약하게 보간한다. 정밀 optical flow는 아니다.
결합anchor + event_memory * CONTRAST_GAIN밝기 변화량을 시각적으로 강조하는 lightweight reconstruction이다.

9. 상황별 이상적인 매칭 전략

해상도 매칭의 기본 원리는 “두 센서의 픽셀 좌표를 같은 물리 좌표계로 보내는 것”이다. 단순히 해상도만 맞추는 것이 아니라, 같은 물체의 같은 점이 두 센서에서 같은 좌표에 오도록 만들어야 한다.

상황권장 매칭이유
같은 렌즈/같은 광축, 해상도만 다름비례 스케일링x'=x*sx, y'=y*sy로 충분할 수 있다. 현재 코드가 이 방식이다.
렌즈 화각이 약간 다름crop + scale넓은 센서 쪽을 crop해서 공통 FOV를 맞춘 뒤 scale한다.
센서 위치가 조금 다름homography평면 장면이나 멀리 있는 장면에서는 3x3 변환 행렬로 좌표계를 맞춘다.
렌즈 왜곡이 있음camera calibration + undistortion체커보드로 내부 파라미터를 구하고 왜곡을 제거한 뒤 매칭한다.
가까운 물체, 깊이 변화 큼stereo/depth-aware warp시차가 커서 단일 homography로는 맞지 않는다. depth 또는 다중 plane 보정이 필요하다.
최고 정합 필요beam splitterCIS와 DVS가 같은 렌즈/같은 광축을 공유하게 만들어 화각 불일치와 parallax를 크게 줄인다.

10. 해상도 차이 처리 시 주의사항

화각 불일치

DVS와 CIS가 서로 다른 렌즈를 쓰면 같은 물체도 크기와 위치가 달라진다. 단순 resize만 하면 가장자리에서 오차가 커진다.

양자화 오차

round(x*sx)는 여러 원본 이벤트를 같은 출력 픽셀에 몰아넣는다. 작은 해상도로 줄일수록 event density와 aliasing을 조심해야 한다.

렌즈 왜곡

광각 렌즈는 중앙과 가장자리 scale이 다르다. 먼저 undistortion을 한 뒤 event 좌표를 변환하는 편이 좋다.

시간 정합

좌표가 맞아도 timestamp가 틀리면 움직이는 물체는 어긋난다. GPIO trigger, PPS, hardware timestamp가 중요하다.

빔스플리터

두 센서가 같은 광축을 공유하게 해 parallax를 줄인다. 대신 광량이 나뉘므로 노출, 노이즈, DVS threshold 설정을 다시 잡아야 한다.

실시간 구현

Python np.add.at는 이해하기 쉽지만 고속에서는 느리다. C++ tile accumulation, SIMD histogram, GPU/FPGA path가 필요하다.

11. 코드 예시: 좌표 정합 후 합성

import numpy as np

# 4x4 grayscale CIS frame
base = np.array([
    [100,100,100,100],
    [100,100,100,100],
    [100,100,100,100],
    [100,100,100,100],
], dtype=np.float32)

# DVS source resolution 8x8, output resolution 4x4
sx = 4 / 8
sy = 4 / 8

events = [
    # x, y, polarity
    (2, 2, +1),
    (3, 2, +1),
    (6, 4, -1),
]

event_memory = np.zeros((4, 4), dtype=np.float32)
for x, y, p in events:
    xo = round(x * sx)
    yo = round(y * sy)
    xo = min(max(xo, 0), 3)
    yo = min(max(yo, 0), 3)
    event_memory[yo, xo] += 1 if p > 0 else -1

gain = 5.0
synth = np.clip(base + event_memory * gain, 0, 255)

print(event_memory)
print(synth)

이 예시에서 DVS 8x8 좌표가 CIS/output 4x4 좌표로 줄어든다. 같은 출력 좌표로 모인 양 이벤트는 밝기를 올리고, 음 이벤트는 밝기를 낮춘다. 실제 코드는 이 과정을 매 target timestamp마다 반복하고, 이전 event_memory를 계속 감쇠시킨다.

12. 고해상도 실시간 합성 설계 메모

결론부터 정리하면, 온디바이스에서 대형 AI 인터폴레이터를 풀프레임으로 돌리는 구조는 채택하지 않는다. 1080p 이상에서 매 출력 프레임마다 neural interpolation을 실행하면 inference latency보다 먼저 메모리 이동, event preprocessing, 후처리, encoder handoff가 병목이 된다. 이 페이지의 데모 구조는 실시간 preview용 경량 합성을 기본 경로로 두고, AI는 움직임 ROI 보정에만 제한해서 사용한다.

설계 원칙:
full_frame_ai = disabled_by_default
realtime_output = lightweight_event_synthesis(full_frame)
enhanced_output = realtime_output + ai_residual(roi_only)

Target Pipeline

CIS MIPI frame
        |
        v
Low-latency base frame buffer
        |
DVS MIPI event stream
        |
        v
Event accumulation + decay
        |
        v
Motion ROI detector
        |
        +--> Full-frame lightweight synthesis --> realtime preview
        |
        +--> ROI crop only --> tiny AI interpolator / residual model
                              |
                              v
                    ROI enhanced patch
                              |
                              v
                    composite back to frame
Realtime path

CIS 최신 프레임을 기준 이미지로 유지한다. DVS event accumulation/decay로 움직임 영역만 갱신한다. 이 경로는 항상 target FPS를 만족해야 한다.

AI path

AI 입력은 active tile 또는 object crop으로 제한한다. 기본 crop 크기는 256x256 또는 384x384로 시작한다. 풀프레임 입력은 benchmark 용도 외에는 사용하지 않는다.

Pyramid path

motion/flow는 저해상도에서 계산한다. 고해상도에서는 edge/detail residual만 보정한다. 필요하면 1/4 scale inference 후 guided upsampling을 적용한다.

Residual model

모델은 새 프레임을 생성하지 않는다. 입력은 lightweight synthesis 결과, event map, ROI mask이고 출력은 correction residual이다.

Async enhancement

preview frame은 즉시 내보낸다. enhanced clip은 N 프레임 늦어도 된다. 웹 UI도 realtime preview와 enhanced result를 분리한다.

Thread boundary

capture, event accumulation, AI inference, encode를 같은 loop에 넣지 않는다. 각 단계는 ring buffer와 timestamp로 연결한다.

Implementation Priority

우선순위전략이유
1MIPI direct input + DMA + zero-copyCIS/DVS 입력을 CPU memcpy 없이 fusion buffer까지 전달한다.
2Event tile index이벤트가 있는 tile만 dirty로 표시한다. dirty tile 외 배경은 재계산하지 않는다.
3Remove full-frame AI from realtime loopAI가 느려져도 preview FPS가 떨어지면 안 된다.

5ROI residual inference작은 ROI에서만 INT8/FP16 모델을 실행한다. 출력은 correction patch다.
6Encoder thread separationhardware encoder queue가 막혀도 fusion thread는 다음 frame을 계속 만든다.

Budget Formula

full_pixels = W * H
roi_pixels = sum(width_i * height_i for active_rois)

ai_cost_ratio = roi_pixels / full_pixels

device_is_possible if:
  lightweight_fusion_fps >= realtime_target_fps
  and roi_ai_latency_ms <= roi_update_budget_ms
  and encoder_fps >= output_stream_fps
  and memory_bandwidth has 30%+ headroom

1080p 한 장은 약 207만 픽셀이다. 320x320 ROI 두 개면 약 20만 픽셀이고 전체의 9.9%다. AI 처리 픽셀 수를 이 수준으로 제한해야 온디바이스 고해상도 합성이 검토 가능한 범위에 들어온다.

Hardware Direction

Raspberry Pi 5는 PoC와 경량 preview 장비로 둔다. 고해상도 AI 보정까지 제품 목표에 넣으면 ISP, NPU/DSP, memory bandwidth, hardware encoder를 같이 봐야 한다. 후보는 IQ8, Jetson Orin, FPGA+NPU SoC, Qualcomm RB 계열이다. 선택 기준은 TOPS 숫자 하나가 아니라 CSI 입력 수, DMA 경로, encoder, sustained memory bandwidth, INT8/FP16 ROI inference latency다.
